Emacs - это старый текстовый редактор Linux типа vim или nano и у него свои правила для регулярных выражений
Когда в документации GNU find написано, что по умолчанию для -regex тип emacs, это значит только одно:
разработчики выбрали ярлык «emacs» для набора правил “какие символы что означают”.К редактору Emacs в этот момент ты не подключаешься то есть «emacs» здесь = название диалекта regex  

Симлинк(символическая ссылка) - условно это ярлык. Хранит в себе путь к другому файлу или каталогу. При удалении файла на который указывает симлинк сам симлинк не удаляется а становится битым. Симлинк может быть относительным(когда ссылка указывающая на файл в нем начинается с места где лежит сам симлинк) и абсолютным(ссылка на файл начинается из корневой директории и тогда не имеет важности откуда мы ее открываем)
ln -s /usr/bin/python3 ~/my-python   # создать симлинк my-python
ls -l ~/my-python                    # увидишь стрелку: my-python -> /usr/bin/python3
В указании пути можно использовать * как порпуск конструкции выбор лежит на имя которое мы просто не указываем

find [путь] [условия] : 
                        Распространенные условия 
    -name 'имя файла' - поиск по имени файла учитывает регистр
    -iname 'имя файла' - поиск по имени файла регистр не учитывается
    -path 'полный путь' - позволяет при наличии двух или более файлов с одним именем выводить определенные 
    -regex 'регулярное выражение' -  прекол надо по новой учить регулярные выражения на всякий случай надо еще понимать какой пакет под регулярные выражения стоит на системе что бы не было неожиданных ошибок
    -type - указатель на формат посика -type f поиск файла, -type d поиск директории, -type l поиск симлинка
    -size [+-]N[cwbkMG] - фильтр по размеру файла 
        +10M — больше 10 МиБ
        -1k — меньше 1 KiB
        0 — пустой (часто удобнее -empty)
        Буква единицы: c байты, w слова по 2 байта, b блоки по 512 байт, k килобайты 1024 байта , M мегабайты , G гигабайты 0_0
    -mtime -atime -ctime - указатели на время какой либо работы с файлом каждый из них кратен 24 часам  
        -mtime - последняя модификация файла 
        -atime - последние взаимодействия с файлом(когда его в последний раз трогали/читали)
        -ctime - последние изменения inode (метаданные) условно права владелец переименовывание итп
    -mmin -amin -cmin - тоже самое только теперь указываем не по 24 часа а по минутам
    -user имя; -group имя - владелец или группа файла как в ls -l 
    -perm MODE
        Фильтр по битам прав (восьмеричный режим, или символьная форма). В GNU find есть нюансы: точное совпадение vs «хотя бы эти биты» (префиксы - и /). Для начала:
        find . -perm 0644             # ровно rw-r--r--
        find . -perm /u+s             # setuid у пользователя выставлен
    -empty - файл нулевой длины или пустой каталог 0_0
    -maxdeph -mindeph - ограничение поиска по подкаталогам директории 
        Ограничить глубину обхода от стартовых путей: 1 = только сама стартовая директория без подкаталогов (для . — только текущий уровень).
        find . -maxdepth 1 -type f    # файлы только здесь, не глубже
        find . -mindepth 2            # пропустить стартовый уровень
        На BSD/macOS синтаксис другой: глубина задаётся флагами перед путём, например find -maxdepth 2 .
    -prune - «Не заходить в этот каталог» — не спускаться внутрь. Почти всегда используется в связке с -path и -o(некое или только в виде указателя). find . -path './node_modules' -prune -o -type f -name '*.js' -print
        Смысл: если путь — node_modules, применить prune (обрезать ветку); иначе искать .js и печатать. Без аккуратной скобочной логики легко получить не то.
    -print - вывести путь найденного; -print0 - те же пути только разделенные нулевым байтом а не переводом строки — безопасно для имён с пробелами и переводами строк.
    -ls - расширенный вывод с метаданными 
    -delete - удалить найденное 
    -a (И)
        Между тестами по умолчанию подразумевается -a. Пишут редко:
        find . -type f -a -name '*.txt'   # то же, что два теста подряд
    -o (ИЛИ)
        find . \( -name '*.jpg' -o -name '*.png' \) -type f
        Скобки ( ) в shell нужно экранировать: \( \) .
    ! или -not
        Инверсия следующего теста:
        find . ! -name '*.bak'
        find . -not -path '*/.git/*'
    -exec исполнительная_команда {} /; - найденное в find мы помещаем в {} и для этого выполняем какую то команду еще есть вариация с -exec исполнительная_команда {} + по сути тоже самое что и было до этого только более оптимизированно. Условно find нашел какие то файлы и с концом /; для каждого из файлов будет вызываться исполнительная команда в случае с + на конце исполнительная команда вызывается единождый и все найденное в find по очереди подставляется в нее. Простыми словами оптимизация ресурсов

locate имя файла или часть имени файла - показывает пути к файлам почти не ходя по каталогам как find. Очень удобная вещь если понимать как она работает. Она ищет по зараннее построенной базе данных которая автоматически обновляется в системе обычно раз в день но может быть одновлена и в ручную. Обычно база называется mlocate.db. База может быть устроена так что она тебе показывает только то на что у тебя есть права видеть 0_0 ппц прикол. Обновление базы данных в ручную sudo updatedb Иногда есть sudo updatedb.plocate / другой бинарник — это зависит от пакета.
полезные флаги:
    -i - игнорировать регистр (Passwd и passwd)
    -c - только количество совпадений, без списка
    -n N - показать только первые N строк
    -0 - печать с \0 вместо перевода строки — для xargs -0
    -S / -s - статистика базы (сколько записей, путь к базе) — точное имя опции зависит от версии; читай man
    -b / --basename - матч только по имени файла, не по полному пути (где поддерживается)
    -r / --regex - регулярное выражение — чаще у plocate и некоторых сборок; у классического набора может не быть

tree - выводит структуру каталогов в виде дерева наглядная карта файлов 
    без аргументов выводит текущий каталог
    основные флаги: 
        -L число_уровней - ограничивает дерево по уровням 
        -a - включает в структуру скрытые файлы 
        -d - убирает видимость файлов и просто показывает скилет системы
        -F - добавляет суффикси / - для каталогов * - для исполняемых файлов @ - для симлинков 
        -f - показывает путь к каждому файлу а не только формат дерева
